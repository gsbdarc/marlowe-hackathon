# A5. Distill a student

**Goal:** train a small model, Qwen 4B, on the labels Qwen 235B wrote in A4, and score it against Jev.

| | |
|---|---|
| Where | Marlowe: 1 H100 per job |
| Data | 5,000 training filings with Qwen 235B's labels, then 1,000 test filings to score |
| Teacher | Qwen 235B, from A4 |
| Student | [Qwen3.5-4B-Base](https://huggingface.co/Qwen/Qwen3.5-4B-Base), trained as a LoRA |
| Before you start | [Step 5 in A4]({{ '/advanced/a4/' | relative_url }}#step-5-label-at-scale) |

Qwen 235B needs a whole node of 8 H100s to run. A model with 4 billion parameters fits on one GPU, or on a laptop,
and answers many times faster. **Distillation** trains the small model, the *student*, to give the answers a large
model, the *teacher*, gives. You pay for the teacher once, to label the training filings, and then use the student.

Kev-27B, in A1, is a student too: of Jev, whose labels are probabilities over the options. Qwen 235B writes its
answer out, so it gives one choice per question and no probabilities. The student learns from those choices.

## Step 1: Get ready

Work from your clone:

```bash
ssh <sunet>@login.marlowe.stanford.edu
cd /scratch/m000106/gsb_hackathon/$USER/marlowe-hackathon
source env/marlowe.sh
```
{: .marlowe }

To have Slurm email you, put your SUNet ID in place of `<sunet>` on the `#SBATCH --mail-user` line of
`slurm/marlowe/advanced/a5_train_student.slurm` and `slurm/marlowe/serve_and_label.slurm`.

If the Qwen 235B server from A4 is still running, stop it now with `scancel <jobid>`: A5 does not need it, and the
node is free for someone else.

## Step 2: Make the training data

Kev's trainer reads one record per filing: the filing, the three questions, and the answer to learn for each.
`make_teacher_data.py` builds those records from the teacher's answers:

```bash
$PY scripts/make_teacher_data.py $WORK/results/qwen-235b-train.jsonl
```
{: .marlowe }

In pseudocode:

<pre class="pseudo"><span class="pc"># scripts/make_teacher_data.py</span>
<span class="pv">answers</span> = the teacher's answers, by filing id
<span class="pk">for each</span> filing in train.jsonl that the teacher answered:
    <span class="pv">status</span> = the teacher's choice, with all the weight on that one option
    <span class="pk">if</span> the teacher says the CEO is leaving:
        add why and future, each with all the weight on the teacher's choice
    write the record to teacher-qwen-235b-train.jsonl
    write the same filing, with Jev's labels, to teacher-jev.jsonl</pre>

It prints how many filings it matched and how many of them the teacher calls CEO changes. The second file,
`teacher-jev.jsonl`, is the same filings with Jev's labels. Training a student on each tells you how much of the
difference comes from the teacher, with the filings held the same.

## Step 3: Train the students

Train one student on each teacher's labels. The two jobs run at the same time, on one H100 each:

```bash
sbatch slurm/marlowe/advanced/a5_train_student.slurm qwen-235b-train
sbatch slurm/marlowe/advanced/a5_train_student.slurm jev
```
{: .marlowe }

The argument names the teacher: the job trains on `$WORK/data/teacher-<teacher>.jsonl` and saves the student in
`$WORK/runs/a5-<teacher>`. Follow a job's log with `tail -f logs/a5-student-<jobid>.out`. Each job takes about 15
minutes.

The jobs run on Marlowe's `preempt` partition, where a job can be stopped to make room for a higher-priority one.
Slurm then puts it back in the queue, and it starts again from the beginning: a LoRA run in Kev's trainer saves no
[checkpoints]({{ '/advanced/a2/' | relative_url }}#checkpoints-saving-the-training-to-disk) to resume from. If a log
starts over, that is what happened.

The trainer is the one from A2, with Kev's settings for its own 4B model:

- **A LoRA**, rank 16, on Qwen3.5-4B-Base. The base model's weights stay as they are, and a small adapter and Kev's
  pointer head learn. The [LoRA section of A3]({{ '/advanced/a3/' | relative_url }}#full-fine-tuning-and-lora)
  explains the trade-off.
- **Learning rate 5e-5**, and 16 filings per optimizer step, as in A2.
- **100 optimizer steps**, so 1,600 of the filings, to fit the session. Kev's full recipe trains for two epochs, so
  the student sees each of the 5,000 filings twice; that takes about an hour on one H100.

Open `slurm/marlowe/advanced/a5_train_student.slurm` to see the full command.

{: .tip }
> If anything in the code is unclear, ask Claude Code or Codex about it.

## Step 4: Score the students

When a student is trained, label the 1,000 test filings with it. `serve_and_label.slurm` serves the model on one H100,
sends it the filings, and scores the answers against Jev's:

```bash
sbatch slurm/marlowe/serve_and_label.slurm $WORK/runs/a5-qwen-235b-train a5-qwen-235b-train
sbatch slurm/marlowe/serve_and_label.slurm $WORK/runs/a5-jev a5-jev
```
{: .marlowe }

The first argument is the model, the second the name of its answers file in `$WORK/results/`. For a model to compare
with, score Kev-4B as released, which is the job's default:

```bash
sbatch slurm/marlowe/serve_and_label.slurm
```
{: .marlowe }

It saves `$WORK/results/kev-4b-zeroshot.jsonl`. When the jobs have finished, put every model side by side, the teacher
from A4 included:

```bash
$PY scripts/score.py \
  $WORK/results/qwen-235b.jsonl \
  $WORK/results/a5-qwen-235b-train.jsonl \
  $WORK/results/a5-jev.jsonl \
  $WORK/results/kev-4b-zeroshot.jsonl
```
{: .marlowe }

`score.py` prints one row per model, with the same columns as in A1 and A4.

<details markdown="1">
<summary>Ideas to explore</summary>

- How close does the student come to its teacher? Where it disagrees with Qwen 235B, which of the two agrees with Jev?
- The two students saw the same filings. What difference does the teacher make?
- How does each student compare with Kev-4B, which was trained on other data, not on these filings?
- What did the teacher's labels cost in GPU-hours (A4), and what did the student's training cost? How many filings
  would the student have to label before it paid for itself?
- Would more training help? Remove `--max_steps 100` and set `--epochs 2` in the job file for Kev's full recipe,
  and give the job `--time=01:30:00`. A4 Step 5 can also label more filings with Qwen 235B.

</details>
