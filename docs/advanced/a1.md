# A1. Score Kev-27B before training

**Goal:** serve Kev-27B on one Yens H200 and measure how often it agrees with Jev. That score is the bar your own
fine-tuned teacher has to reach in A2.

| | |
|---|---|
| Where | Yens, 1 H200 |
| Data | the 1,000 test filings (2022 to 2026) with Jev's labels |
| Model | Kev-27B (`jaredpalmer/kev-27b@af0e6d5`), 51 GB of weights, built on Qwen3.8-27B |
| Time | about 15 minutes |

---

## The commands, in order

These are all the commands in this task. The steps below explain them as you go.

| Command | What it does |
|---|---|
| `ssh <sunet>@yen.stanford.edu` | Logs you in to an interactive Yen node (`yen1` to `yen5`). Installs and downloads run here. GPU work goes through Slurm. |
| `cd /scratch/users/$USER/marlowe-hackathon` | Moves to your own clone of this repository, made in [Before You Arrive]({{ '/setup/' | relative_url }}). |
| `source env/yens.sh` | Sets the paths every script uses: `$DATA` (Jev's filings), `$WORK` (your data, runs and results), `$KEV_HOME` (your Kev install) and `$HF_HOME` (model weights). Run it again in every new terminal. |
| `bash scripts/setup_kev.sh` | Installs Kev's code and Python environment in `$KEV_HOME`, once. It takes about 10 minutes and is safe to rerun. |
| `cp /scratch/shared/marlowe_hackathon/data/test1000.* $WORK/data/` | Copies the 1,000 test filings, and Jev's answers for them, from the shared read-only data folder to where the job reads them. |
| `mkdir -p logs` | Creates the folder Slurm writes job output to. It must exist before you submit. |
| `sbatch slurm/yens/advanced/a1_score_kev27b.slurm` | Submits the job to Slurm and prints its job ID. The job asks for one H200. |
| `squeue --me` | Lists your jobs. `PD` is waiting for a GPU, `R` is running, and the job leaves the list when it ends. |
| `tail -f logs/adv-a1-kev27b-<jobid>.out` | Follows the job's output as it is written. Ctrl-C stops following; the job keeps running. |

## Step 1: Set up on the Yens

Log in and work from your own clone of this repository, in your scratch space. `ssh yen.stanford.edu` puts you on an
interactive node (`yen1` to `yen5`), a full-size server where you can install and download directly.

```bash
ssh <sunet>@yen.stanford.edu
cd /scratch/users/$USER/marlowe-hackathon
source env/yens.sh
```
{: .yens }

If you have not cloned it yet, follow [Before You Arrive]({{ '/setup/' | relative_url }}). If Kev is not installed yet,
install it once (about 10 minutes):

```bash
bash scripts/setup_kev.sh
```
{: .yens }

Jev's data is in `/scratch/shared/marlowe_hackathon/data/`, readable by everyone on the Yens. Copy the test filings
into your own work folder, where the job reads them:

```bash
mkdir -p $WORK/data
cp /scratch/shared/marlowe_hackathon/data/test1000.* $WORK/data/
```
{: .yens }

## Step 2: Submit the job

```bash
mkdir -p logs
sbatch slurm/yens/advanced/a1_score_kev27b.slurm
```
{: .yens }

The job asks for one H200 (`-C GPU_MODEL:H200`), because Kev-27B's 51 GB of weights do not fit on an A40's 48 GB. It
starts a Kev server on the GPU, sends it the 1,000 test filings and scores the answers against Jev.

## Step 3: Read the scores

```bash
tail -f logs/adv-a1-kev27b-<jobid>.out
```
{: .yens }

The server log, `logs/kev-server-<jobid>.log`, shows the weights loading. When labeling finishes, the scores print at
the end of the job log. DARC's earlier run on an H200 agreed with Jev on about 95% of filings and about 87% of CEO
changes, at about 5 filings per second.

{: .checkpoint }
> **A1.** Post Kev-27B's agreement with Jev on CEO changes and its filings per second in Slack. Then put up a 🟩
> green sticky. 🟥 if you are stuck.

## If it fails

- **The job waits in the queue:** the Yens have two H200s. `squeue --me` shows why it is waiting.
- **`Kev server stopped`:** the server log says why. The first run downloads the 51 GB of weights into `$HF_HOME`,
  which takes longer than the scoring.
