# A3. Fine-tune on two nodes

**Goal:** run the A2 fine-tune across two full Marlowe nodes, 16 H100s, and compare its time per step with one node.

| | |
|---|---|
| Where | Marlowe: 2 nodes, 16 H100s |
| Data | 54,426 filings (2004 to 2018) with Jev's labels |
| Model | [Qwen3.8-27B](https://huggingface.co/Qwen/Qwen3.8-27B) |
| Trainer | Kev's trainer, the same full fine-tune as A2 |
| Before you start | [A2]({{ '/advanced/a2/' | relative_url }}): setup done, and the 8-GPU run finished |

The training is the same as A2's: 100 optimizer steps of 16 filings each. With 16 GPUs, each step gives one filing
to each GPU at once, where 8 GPUs took two passes of 8.

## Step 2: Fine-tune on two nodes

```bash
sbatch slurm/marlowe/advanced/a3_train_2node.slurm
```
{: .marlowe }

The job asks for two whole nodes, so it can wait in the queue longer than A2's. Slurm starts one copy of `torchrun`
on each node, and each starts 8 trainer processes, one per GPU. The 16 processes find each other through the first
node of the job and share the model 16 ways with FSDP.

Follow the log:

```bash
tail -f logs/a3-27b-2node-<jobid>.out
```
{: .marlowe }

Every line starts with the minutes and seconds since the job began. After the model loads, the trainer prints a line
every 10 optimizer steps; `world=16` in its first line is the 16 GPUs. Each node also writes its own GPU log,
`logs/gpu-<jobid>-<node>.csv`.

## Step 3: Compare with one node

When the log prints `saved`, compare the two runs:

```bash
$PY scripts/step_times.py $WORK/runs/a2-8gpu $WORK/runs/a3-2node
```
{: .marlowe }

It prints, for each run, the GPUs, the seconds per optimizer step, the peak GPU memory, and the hours and GPU-hours one
epoch would take. Then see how busy the GPUs were on each job:

```bash
$PY scripts/gpu_util.py logs/gpu-*.csv
```
{: .marlowe }

It prints one row per job: the GPUs, their average and peak utilization, and the most memory any one GPU held. The
two-node job's two GPU logs, one per node, come out as one row of 16 GPUs. A2 Step 4 explains each column.

<details markdown="1">
<summary>After you compare: what the numbers mean</summary>

**Speedup.** Divide the one-node `s/step` by the two-node `s/step`. 2 would be perfect: twice the GPUs, half the
time. Expect close to 2, but not quite. With FSDP, the GPUs exchange each layer's weights before using it and the
gradients after. Inside one node the 8 H100s talk over NVLink; between nodes the traffic crosses InfiniBand, which is
slower. With 16 GPUs, every exchange crosses that link, so some of the time the second node saves goes to waiting.

**Memory.** Each GPU holds half as much of the model as on one node, so the peak memory per GPU drops. It does not
halve: each GPU still trains on one filing at a time, and the memory for that filing stays the same.

**Cost.** A run's cost is its GPU-hours: the number of GPUs times the hours they run, which is `epoch GPU-hours`.
Two nodes use twice as many GPUs as one node. If they also took exactly half the time, the cost would be the same. They take a
little more than half, so the same epoch uses a few more GPU-hours. For example, if 8 GPUs took 10 hours, that is 80
GPU-hours; if 16 GPUs took 5.5 hours, that is 88. The second node gets you the result sooner, for a little more
compute.

</details>

## Step 4: Where did the time go?

Compare your 8-GPU and 16-GPU runs in more detail, and make at least one plot. Work in a Jupyter notebook in Marlowe's
Open OnDemand, or ask Claude Code to load the files and make the plots for you. Find out:

- How many times faster is a step on 16 GPUs than on 8, and how close is that to 2×?
- Does the whole job run twice as fast, or only the training? How long does each job spend loading the model,
  preparing the data, training and saving?
- How busy were the GPUs on each run, and when?
- With a fixed budget of GPU-hours, which would you choose?

| File | What is in it |
|---|---|
| `$WORK/runs/a2-8gpu/training_metrics.json` and `$WORK/runs/a3-2node/training_metrics.json` | each run's timing: `step_seconds` (the time of each of the 100 steps), `wall_seconds` (the training time), `world_size` (the GPUs) and more |
| `logs/a2-27b-8gpu-<jobid>.out` and `logs/a3-27b-2node-<jobid>.out` | the job logs, every line stamped with the minutes and seconds since the job began |
| `logs/gpu-<jobid>.csv` and `logs/gpu-<jobid>-<node>.csv` | each GPU's memory and utilization every 15 seconds |
