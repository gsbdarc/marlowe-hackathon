# A2. The teacher labels the filings

**Goal:** have your fine-tuned Kev-27B label every training filing, and the 1,000 test filings, across two full
Marlowe nodes.

| | |
|---|---|
| Where | Marlowe, 2 nodes (16 H100s) |
| Data | the 54,426 training filings and 1,000 test filings; Jev's labels are used only to score the teacher |
| Model | your fine-tuned Kev-27B from A1, or DARC's |
| Time | about 30 minutes |

---

## Labeling scales differently from training

Serving Kev-27B fits on one GPU (it uses about 66 GB). Each GPU can run its own copy of the model and label its own
share of the filings, with no communication between GPUs, so 16 GPUs label about 16 times as fast as one. Training
does not scale that way, because the GPUs exchange results at every step.

## Step 1: Submit

```bash
cd $WORK
sbatch $ADV/slurm/a2_label_2node.slurm
```
{: .marlowe }

If A1 did not finish, use DARC's fine-tuned teacher instead:

```bash
RUN=$TEACHER_FALLBACK sbatch $ADV/slurm/a2_label_2node.slurm
```
{: .marlowe }

The job:

1. splits the training and test filings into 16 shards (`scripts/make_shards.py`);
2. starts 16 tasks with `srun`, 8 per node, one GPU each;
3. in each task, starts a Kev server on that GPU and labels that task's shard (`slurm/a2_label_task.sh`);
4. merges the shards into `$WORK/a2/kev27b_labels.jsonl` and scores the teacher against Jev on the test filings.

## Step 2: Watch it

```bash
tail -f logs/adv-a2-label-<jobid>.out
tail -2 $WORK/a2/logs/label-<jobid>-00.log
```
{: .marlowe }

Each task's log reports its filings per second. Each task prints `task NN: done` when its shard is finished, and the
job ends with the count of filings answered and the teacher's scores.

## If it fails

- **The job was preempted or hit its time limit:** submit the same command again. Each shard skips the filings it
  has already answered.
- **`Kev server stopped`:** the server log, `$WORK/a2/logs/server-<jobid>-NN.log`, says why.
